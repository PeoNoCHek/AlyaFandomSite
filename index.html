1. Общая характеристика системы

Разрабатываемое веб-приложение представляет собой информационно-коммуникационную платформу, объединяющую:

  • энциклопедический раздел с пользовательским созданием и редактированием материалов;
  • каталог произведений и связанных с ними объектов;
  • персональные пользовательские списки и оценки;
  • систему отзывов, рецензий и комментариев;
  • тематические сообщества и обсуждения;
  • форум с разделами, темами и сообщениями;
  • систему пользователей, ролей, репутации и модерации.
Архитектура ориентируется на отдельные идеи Fandom, Shikimori и 4PDA, но приложение должно иметь собственную структуру интерфейса, модели данных и бизнес-логику.

2. Роли пользователей

FR-01
Гость

Гость должен иметь возможность:

  • просматривать общедоступные страницы;
  • просматривать каталог;
  • выполнять поиск;
  • просматривать профили пользователей;
  • читать отзывы, рецензии, комментарии и темы форума;
  • регистрироваться и выполнять вход.

Ограничение: гость не должен иметь возможности создавать или изменять пользовательский контент.

FR-02
Зарегистрированный пользователь
  • редактировать собственный профиль;
  • добавлять материалы в персональные списки;
  • оценивать объекты каталога;
  • писать отзывы и рецензии;
  • создавать комментарии;
  • создавать темы и сообщения форума;
  • подписываться на интересующие объекты;
  • отправлять личные сообщения;
  • взаимодействовать с другими пользователями;
  • изменять репутацию пользователей по правилам системы.
FR-03
Автор / редактор
  • создавать энциклопедические статьи;
  • редактировать существующие статьи;
  • добавлять категории;
  • добавлять изображения и другие разрешённые материалы;
  • просматривать историю изменений;
  • отменять ошибочные изменения;
  • создавать связанные страницы.
FR-04
Модератор
  • редактировать и удалять нарушения в пользовательском контенте;
  • скрывать или удалять комментарии;
  • закрывать и переносить темы форума;
  • выдавать предупреждения пользователям;
  • временно блокировать пользователей;
  • рассматривать жалобы;
  • контролировать соблюдение правил сообщества.
FR-05
Администратор

Полный доступ к управлению системой:

  • пользователями;
  • ролями;
  • правами доступа;
  • разделами;
  • категориями;
  • настройками системы;
  • модерацией;
  • статистикой;
  • справочниками;
  • системными настройками.

3. Регистрация и авторизация

FR-06
Регистрация

Форма регистрации с использованием:

  • имени пользователя;
  • адреса электронной почты;
  • пароля;
  • подтверждения пароля.

Система должна проверять уникальность имени пользователя и корректность введённых данных.

FR-07
Авторизация

Вход в систему по учётным данным.

FR-08
Восстановление доступа

Восстановление пароля посредством электронной почты.

FR-09
Выход

Завершение текущей сессии.

4. Пользовательский профиль

FR-10
Просмотр профиля

Система должна отображать:

  • аватар;
  • имя пользователя;
  • дату регистрации;
  • описание пользователя;
  • репутацию;
  • количество созданных материалов;
  • количество сообщений;
  • пользовательские списки;
  • отзывы и рецензии;
  • историю активности.
FR-11
Редактирование профиля
  • аватар;
  • имя / отображаемое имя в разрешённых пределах;
  • описание;
  • настройки приватности;
  • уведомления.
FR-12
История активности
  • создание статьи;
  • изменение статьи;
  • создание темы;
  • публикацию сообщения;
  • написание отзыва;
  • добавление объекта в список;
  • получение реакции от других пользователей.

5. Каталог объектов

Одним из основных разделов системы должен быть единый каталог.

FR-13
Просмотр каталога

Для объекта должны храниться (в зависимости от типа):

  • название;
  • альтернативные названия;
  • описание;
  • изображение / обложка;
  • дата выхода;
  • статус;
  • категории;
  • жанры;
  • авторы;
  • студии / создатели;
  • связанные объекты;
  • рейтинг;
  • количество пользовательских оценок.
FR-14
Фильтрация каталога

Фильтры по характеристикам: тип, жанр, категория, год, сезон, возрастной рейтинг, статус, создатель, студия, рейтинг.

FR-15
Сортировка
  • по рейтингу;
  • по популярности;
  • по дате;
  • по количеству оценок;
  • по алфавиту;
  • по активности пользователей.
FR-16
Карточка объекта

Отдельная страница с полной информацией: описание, характеристики, рейтинг, отзывы, рецензии, комментарии, связанные объекты, пользовательские списки, энциклопедические статьи.

6. Персональные списки пользователей

FR-17
Добавление объекта в список

Персональные статусы: «хочу посмотреть», «смотрю», «просмотрено», «отложено», «брошено». Набор статусов настраивается администрацией.

FR-18
Оценка объекта

Пользователь может выставить оценку по заданной шкале.

FR-19
Персональная статистика
  • количество просмотренных объектов;
  • количество объектов в каждом статусе;
  • средняя оценка;
  • наиболее часто используемые жанры;
  • активность пользователя.

7. Отзывы и рецензии

FR-20
Создание отзыва

Отзыв содержит: текст, оценку, дату публикации, автора.

FR-21
Создание рецензии

Рецензия поддерживает: заголовок, форматированный текст, изображения, оценку, автора, дату публикации.

FR-22
Реакции на отзывы
  • положительная реакция;
  • отрицательная реакция;
  • комментарий;
  • жалоба на нарушение.

8. Энциклопедия / Wiki

Функциональный блок, вдохновлённый Fandom.

FR-23
Создание статьи

Статья содержит: заголовок, краткое описание, основной текст, изображения, категории, ссылки на связанные материалы.

FR-24
Редактирование статьи

Пользователь с правами редактора может изменять существующую статью.

FR-25
История изменений

Для каждого изменения сохраняется: автор, дата и время, предыдущая версия, новая версия, описание изменения.

FR-26
Просмотр старой версии

Пользователь с соответствующими правами может просмотреть предыдущую версию статьи.

FR-27
Восстановление версии

Редактор или модератор может восстановить выбранную версию статьи.

FR-28
Категории
  • создание категорий;
  • добавление статьи в категорию;
  • удаление статьи из категории;
  • просмотр всех статей категории.
FR-29
Связи между статьями

Статья должна иметь ссылки на другие статьи и объекты каталога.

9. Комментарии и обсуждения

FR-30
Комментарии

Комментарии к статьям, объектам каталога, отзывам, рецензиям, коллекциям и другим разрешённым материалам.

FR-31
Ответы на комментарии

Поддержка древовидных ответов.

FR-32
Редактирование и удаление

Автор может изменить или удалить собственный комментарий в течение установленного правилами периода или при соблюдении заданных условий.

FR-33
Жалоба

Возможность отправить жалобу на комментарий.

10. Тематические сообщества

FR-34
Создание сообщества

При создании указываются: название, описание, изображение, категория, правила, настройки приватности.

FR-35
Участники сообщества
  • вступить в открытое сообщество;
  • покинуть сообщество;
  • просматривать список участников.
FR-36
Материалы сообщества

Публикации, обсуждения, комментарии, прикреплённые материалы, опросы.

11. Форум

Форум должен быть отдельной подсистемой, вдохновлённой структурой 4PDA.

FR-37
Разделы форума

Иерархия: Раздел → Подраздел → Тема → Сообщение.

FR-38
Создание темы

Тема содержит: заголовок, описание / первое сообщение, автора, дату создания, категорию.

FR-39
Публикация сообщений

Возможность отвечать в существующей теме.

FR-40
Управление темой (модератор)
  • закрепить тему;
  • закрыть тему;
  • перенести тему;
  • переименовать тему;
  • удалить тему;
  • объединить дублирующиеся темы.
FR-41
Вложения

Возможность прикреплять разрешённые файлы и изображения.

FR-42
Цитирование

Поддержка цитирования предыдущих сообщений.

FR-43
Редактирование сообщения

Автор может редактировать собственное сообщение согласно правилам форума.

12. Поиск

Поиск должен быть одной из основных функций системы.

FR-44
Глобальный поиск

Поиск по: пользователям, статьям, объектам каталога, темам, сообщениям, отзывам, рецензиям, сообществам.

FR-45
Расширенный поиск

Дополнительные параметры: раздел, автор, дата, категория, тип контента, сортировка.

FR-46
Поиск внутри темы

Поиск сообщений непосредственно внутри выбранной темы.

13. Подписки и уведомления

FR-47
Подписка

На: тему форума, статью, объект каталога, сообщество, пользователя.

FR-48
Уведомления
  • о новом ответе;
  • о комментарии;
  • о реакции;
  • о личном сообщении;
  • об изменении подписанного материала;
  • о действиях модерации.

14. Личные сообщения

FR-49
Обмен сообщениями

Авторизованные пользователи могут отправлять друг другу личные сообщения.

FR-50
Диалоги

История переписки между пользователями.

FR-51
Управление сообщениями
  • удалить сообщение;
  • архивировать диалог;
  • отметить сообщение как прочитанное / непрочитанное;
  • заблокировать получение сообщений от пользователя.

15. Репутация и социальные функции

FR-52
Репутация пользователя

Пользователь имеет показатель репутации.

FR-53
Изменение репутации

Возможность изменить репутацию другого пользователя при соблюдении установленных условий.

FR-54
История репутации
  • кто изменил репутацию;
  • кому;
  • значение изменения;
  • дата;
  • основание / комментарий.

16. Модерация

FR-55
Жалобы

Жалобы на: сообщение, комментарий, статью, пользователя, вложение.

FR-56
Панель модератора

Списки: новых жалоб, нарушений, подозрительных материалов, заблокированных пользователей, последних действий.

FR-57
Модерационные действия
  • удалить материал;
  • скрыть материал;
  • изменить материал;
  • выдать предупреждение;
  • временно заблокировать пользователя;
  • передать жалобу администратору.
FR-58
Журнал модерации

Все значимые действия модераторов фиксируются в журнале.

  • заблокировать / разблокировать пользователя;
  • изменить права;
  • просмотреть историю активности.
FR-60
Управление ролями

Создание ролей и назначение им прав.

FR-61
Управление категориями

Создание, изменение и удаление категорий.

FR-62
Управление контентом

Просмотр и изменение любого пользовательского контента в рамках полномочий.

FR-63
Статистика системы
  • количество пользователей;
  • количество публикаций;
  • количество тем;
  • количество сообщений;
  • количество статей;

  • активность пользователей.

18. Медиа и файлы

FR-64
Загрузка изображений

Пользователь с соответствующими правами может загружать изображения.

FR-65
Вложения

Ограничения: размер файла, допустимые форматы, количество файлов, права на доступ.

FR-66
Предпросмотр

Для поддерживаемых типов изображений система должна создавать предпросмотр.

19. Связи между подсистемами

Одной из ключевых особенностей проекта должна стать взаимосвязь разных типов контента. Например, карточка объекта каталога должна быть связана с:

Объект → Wiki-статьи → Отзывы → Рецензии → Обсуждения → Пользовательские списки → Сообщества → Форумные темы

Это позволит пользователю переходить между информационной и социальной частью системы без повторного поиска объекта.

3. Персональные спискидобавить объект; изменить статус; поставить оценку.
4. Wikiстатьи; создание; редактирование; категории; история изменений.
5. Обсуждениякомментарии; ответы; оценки; жалобы.
6. Форумразделы; темы; сообщения; поиск; вложения.

  • подписки;
  • уведомления;
  • личные сообщения;
  • сообщества;
  • коллекции;
  • достижения;
  • расширенную статистику;
  • рейтинги пользователей;

  • расширенный поиск;
  • систему тегов;
  • опросы;
  • избранное;
  • API для внешних приложений.

22. Основные пользовательские сценарии

Сценарий 1. Поиск объекта

Пользователь → вводит запрос → система выполняет поиск → отображает результаты → пользователь применяет фильтры → открывает карточку объекта.

Сценарий 2. Добавление в список

Пользователь → открывает карточку → выбирает статус → система добавляет объект в персональный список → обновляет статистику пользователя.

Сценарий 3. Создание статьи

Редактор → создаёт статью → заполняет содержимое → выбирает категории → публикует → система сохраняет новую версию → статья становится доступна пользователям.

Сценарий 4. Создание темы

Пользователь → выбирает раздел → создаёт тему → публикует первое сообщение → другие пользователи отвечают → автор получает уведомления.

Сценарий 5. Модерация

Пользователь → отправляет жалобу → жалоба появляется в панели модератора → модератор рассматривает материал → выполняет действие → система записывает действие в журнал.

24. Приоритеты требований

Для планирования разработки требования рекомендуется разделить на три уровня.

MUST HAVE
Без них система не считается работоспособной

Регистрация, авторизация, профили, каталог, поиск, карточки объектов, персональные списки, статьи, комментарии, форум, базовая модерация.

SHOULD HAVE
Желательно реализовать

Рейтинги, отзывы, рецензии, подписки, уведомления, репутация, сообщества, расширенный поиск.

COULD HAVE
Функции последующих версий

Достижения, рекомендации, умная персонализация, расширенная аналитика, API, автоматическая синхронизация.

Главная функциональная идея проекта

В отличие от простого форума или каталога, система должна объединять три типа работы пользователя:

Тип работыПодсистемы
1. Получить информациюКаталог + Wiki
2. Организовать личную информациюСписки + оценки + избранное + коллекции
3. ОбщатьсяКомментарии + сообщества + форум + личные сообщения
Именно это стоит сделать центральной концепцией проекта.
